# Database Recovery - September 13, 2026

## Issue
The EdGraph SQLite database (`packages/nextjs/.data/edgraph.sqlite`) was corrupted, causing:
- Policies API returning no data
- Claims API returning no data
- Dashboard showing 0 policies and 0 claims
- Database integrity errors (btree corruption, missing index entries)

## Root Cause
Multiple corruption events occurred (evidenced by backup files with timestamps):
- `edgraph.sqlite.corrupt-backup` (2026-09-12 17:36)
- `edgraph.sqlite.corrupt-20260912-201852` (2026-09-12 20:18)
- `edgraph.sqlite.corrupt-20260913-003541` (2026-09-13 00:35)

The corruption manifested as:
- Btree page errors
- Missing index entries in observations table
- Row ordering issues

## Recovery Steps Taken

### 1. Database Dump
Attempted to dump data from the corrupt database:
```bash
sqlite3 edgraph.sqlite ".dump" > /tmp/edgraph_dump.sql
```
Successfully recovered:
- 11 policies
- Schema structure
- Partial observations data

### 2. Fresh Database Creation
Removed the corrupt database and let the migration system rebuild it:
```bash
# Backed up corrupt database
mv edgraph.sqlite edgraph.sqlite.corrupt-final-backup

# Application automatically created fresh database via migrations
# Migrations applied: 001_initial, 002_evidence_payment_unique, 003_update_claims_schema
```

### 3. Data Restoration
Extracted and restored policy data:
```bash
grep "INSERT INTO policies" /tmp/edgraph_dump.sql > /tmp/restore_policies.sql
sqlite3 edgraph.sqlite < /tmp/restore_policies.sql
```

## Important Notes

### Data Architecture
The EdGraph system uses a **hybrid data model**:

1. **On-Chain Source of Truth** (Hedera):
   - Policy terms stored on PolicyRegistry contract
   - Policies API reads from chain via `listPoliciesFromHedera()`
   - Total on-chain: 19 policies

2. **Local Database (SQLite)**:
   - Caches policy data for performance
   - Stores observations, claims, evidence, payments
   - Used by worker processes and agent workflows

### Why Dashboard Shows Data Despite Empty Database
The policies shown in the UI come from the Hedera blockchain, not the local database. The `upsertPolicy()` call in the API gradually repopulates the local cache as policies are accessed.

### Monitor Process
The EdGraph monitor process will automatically:
- Fetch policy data from chain
- Collect new observations
- Detect potential claims
- Populate the database over time

## Prevention Recommendations

1. **Enable WAL Mode Checkpointing**: Already enabled via `database.pragma("journal_mode = WAL")`

2. **Monitor Disk Space**: SQLite corruption can occur when disk space is exhausted

3. **Graceful Shutdown**: Ensure Next.js and monitor processes are stopped gracefully (not killed)

4. **Regular Backups**: Consider adding periodic database dumps:
   ```bash
   sqlite3 .data/edgraph.sqlite ".dump" > backups/edgraph-$(date +%Y%m%d-%H%M%S).sql
   ```

5. **Database Size Monitoring**: The observations table can grow large; consider implementing data retention policies
